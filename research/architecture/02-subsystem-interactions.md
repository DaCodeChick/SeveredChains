# Subsystem Interactions and Dependencies

Status: Foundational pass (R1). Repository: Severed-Chains @ `0c08c679b`.

This document gives the concrete interaction maps: who calls whom when. Complements `01-runtime-subsystems.md` (what things are) and `03-state-and-ownership.md` (who owns what, under which locks).

## 1. Per-frame interaction sequence (steady state)

One iteration of the platform loop (main thread unless noted). `→` = synchronous call; `[E]` = event posted; `async` = crosses to another thread.

```
INPUT TICK (input Action, rate hz)
  SdlPlatformManager.tickInput [INPUT_LOCK]
    SDL_PollEvent loop:
      window events        → SdlWindow (focus/resize/close)
                             resize → RenderEngine.onResize (sets resize flag, recompute render size)
                             close  → window.close()
      key/button/axis      → WindowEvents callbacks:
                                RenderEngine handlers (freecam/speed/pause/debug)
                                game state inputActionPressed/Released (bindRendererEvents)
                                InputPressedEvent/ReleasedEvent [E] → mod listeners (EventManager)
      gamepad axis         → deadzone → axis-action state
    repeats                → onInputActionPressed(repeat) + events [E]
    rumble lerp update

RENDER TICK (window render Action, rate hz — same iteration, after input)
  SdlWindow.tick
    SDL_GL_SwapWindow                     (present previous frame)
    WindowEvents.onDraw
      RenderEngine onDraw:
        flush addTask queue
        deferred render-buffer resize
        pre() [frameSkipIndex==0]: viewport, projection, clear
        EVENTS.clearStaleRefs
        [pause/frame-advance handling — debugger]
        ignoreQueues = (frameSkipIndex != 0)
        renderFrame:
          renderCallback.run()  ══════► GAME LOOP (Scus94491BpeSegment.gameLoop)
            Graphics.endFrame   (PSX mask commands, sync, display-buffer swap)
            GPU.startFrame      (VRAM→texture if dirty; ordering-table resize)
            timestamp += vsyncMode [if state.advancesTime()]
            hz recompute → RENDERER.window.setFpsLimit + PLATFORM.setInputTickRate
            loadQueuedOverlay [state transition; EngineStateChangeEvent [E]]
            renderUi / state.tick / RENDER_EVENT [E] / loadAndRenderMenus
            uploadRenderables
            SCRIPTS.tick        (Fate VM frame)
            state.postScriptTick
            battle transition / full-screen effects
            startQueuedSounds   (SPU key-on queue → SPU.keyOn word)
            textboxes
            state.overlayTick
            FUN_80020ed8 (submap transition flags)
            tickCount++
            GPU.endFrame        (z-queue render; display present in legacy/VRAM modes)
            DISCORD.tick
          (script natives inside SCRIPTS.tick may call any subsystem facade:
           Audio.*, SPU, GPU, REGISTRIES, SAVES via gameState, Loader async, etc.)
        render batches (sort → opaque 3D/2D → translucent 3D/2D)
        post-process pass (CRT/roll/bloom/… → window)
        bookkeeping (buffer index, vsyncCount, FPS, deletes)
        [shader reload; handleMovement]
    clearPressed
  sleep until next due action
```

Cross-thread traffic generated by one frame (main → others):

- `SPU.keyOn(voices)` / `SPU.setReverb*` / volumes (main → SFX-thread model; lock: `synchronized(Spu.class)` on the SFX side only — see ownership doc §4).
- `AUDIO_THREAD.*` control (main → OPEN_AL; `synchronized(AudioThread)`).
- `Loader.load*` → `Async.run` (main → Async pool; callbacks return on pool threads → e.g., VRAM upload under `vramLock`).
- `SAVES` campaign load (main → Async pool `CompletableFuture`, result consumed on main).
- `DISCORD` update (main → SDK internal).
- RenderEngine tasks (`addTask`) are the reverse direction: any thread can schedule a frame-start task onto the main thread.

`Verified` (call sites).

## 2. Initialization interactions (startup)

```
main:  UPDATER.check ──(HTTP callback)──► UPDATE set [UPDATER_LOCK]
       (unpack thread)  loadGfx render callback registered (before RENDERER.init — safe: only read at onDraw time)
       main:  PLATFORM.init → [window created later, in RENDERER.init]
       unpack thread starts:
            Unpacker.unpack (ISO → files/)          [status → statusText, read by renderIntro]
            ScriptPatcher.apply (files/ patches)
            await UPDATE_CHECK_FINISHED             [UPDATER_LOCK]
            unpackerLoading = false                 [INIT_LOCK]
       main:  bootMods → findMods/loadMods/registries/bindings/lang
              ConfigStorage.loadConfig
              AUDIO_THREAD.init → sources (sequencer, xa)
              SPU.init → AUDIO_THREAD.addSource(spu source)
              RENDERER.init (window, shaders, onDraw)
              GPU.init
              openalThread.start → 120 Hz loop (audio thread)
       (render loop runs: loadGfx/renderIntro frames; input handlers active)
       when gate open: transitionToGame [INIT_LOCK]
            Scus94491BpeSegment.main (gameInit/preload; VRAM font/shadow uploads)
            loadMenuAssets / textbox geometry / battle UI
            Audio.startSound → SFX thread (60 Hz: game Sequencer + SPU)
            bindRendererEvents (gameLoop becomes the render callback)
            Fmv.playCurrentFmv(0, TITLE) → FINAL_FMV-ish playback → TITLE state
       later (on first game menu open or as needed): bootRegistries
            remaining registries + texture atlas pack (RegisterAtlasTexturesEvent)
```

`Verified` (ordering). Note the deliberate pattern: *everything that the first rendered frame might touch is initialized before `RENDERER.run()`*, and the only post-run initialization is the SFX thread (started at transition) — audio silence during the intro is by design.

## 3. Data flows

### 3.1 Assets (startup + runtime)

```
ISO (isos/*.iso) ──Unpacker.unpack──► files/ (plain-file cache; MRG-leaf transformed)
files/ ──Loader (Async pool)──► FileData ──► consumers:
    game code (decoders: TMD/CTMD/ANIM/TIM/MCQ/SSSQ/XA-opus/FMV) ──► GPU VRAM [vramLock]
    GPU VRAM ──(startFrame)──► vramTexture15/24 (GL) ──► shaders
    TMD containers ──► Obj (meshes) + Model124 ──► queueModel ──► pools ──► GL
    SSSQ assets ──► core sequencer (OPEN_AL thread)
    XA (.opus) ──► XaPlayer (OPEN_AL thread)
```

### 3.2 Audio

```
BGM: game Audio facade (main) ──loadBackgroundMusic/startSequence (synchronized)──►
     core Sequencer (OPEN_AL) ──120 Hz tick──► OpenAL buffers ──► device
SFX: script natives (main) ──► Audio queue / SPU.keyOn ──► SPU model (SFX thread, 60 Hz)
     ──► GenericSource ──(canBuffer/bufferOutput)──► OpenAL (consumed by OPEN_AL loop) ──► device
XA:  script natives (main) ──► AUDIO_THREAD.loadXa ──► XaPlayer (OPEN_AL) ──► device
```

### 3.3 Script ↔ world

```
SCRIPTS.tick (main) ── native call ──► 1024-entry table (global + per-state) ──► game facades
scripts read/write: gameState (GameState52c fields via stor/gamevar params),
REGISTRIES entries (scriptReadRegistryEntryVar → ScriptReadable),
SPU/Audio/GPU/Loader directly (natives in Audio/RenderEngine/… classes)
mods observe: InputPressed/ReleasedEvent, EngineStateChangeEvent, ScriptFlags*ChangedEvent,
ReadGlobalFlagsEvent (cancellable — mods can override script flag reads)
```

## 4. Event flows (per-frame and lifecycle)

| Event | When | Producer | Consumers | Cancelable |
|---|---|---|---|---|
| `RenderEvent` | every frame (gameLoop phase 7) | gameLoop | mods | no |
| `InputPressedEvent` / `InputReleasedEvent` | input tick (edges, repeats) | tickInput / triggerBinding* | game-adjacent listeners, mods | no |
| `EngineStateChangeEvent` | frame top on transition | loadQueuedOverlay | mods (old, new) | no |
| `ScriptFlags1/2ChangedEvent` | script set-global-flag natives | script natives | mods (can override the set value) | **yes** (payload mutation) |
| `ReadGlobalFlagsEvent` | script read-global-flag natives | script natives | mods (can override the read value) | **yes** (payload mutation) |
| `RegisterAtlasTexturesEvent` | bootRegistries | bootRegistries | mods (contribute images) | no |
| per-registry `Register*` events | mod boot | bootMods | mods | no |
| per-registry add/remove events | runtime registry mutation | registries | mods | no |
| `RegisterDefaultInputBindingsEvent` | bootMods | InputBindings.initBindings | mods | no |

`Verified` (all posted/registered at the cited sites).

## 6. Failure interactions

- **Crash** (any thread throwing into the top-level handler or an uncaught pool-thread exception): the JVM-level net is only `Main.main`'s catch for the main thread. Async-pool task exceptions propagate into the `CompletableFuture` (observed consumers of file-load futures generally do not attach failure handlers — a failed load surfaces as an uncompleted future / `CompletionException` at the await site; `Inferred` for the general case, `Verified` for the unpack path which has explicit handling).
- **Audio thread death**: `AudioThread.run`'s loop is wrapped per-iteration only in `synchronized` — an unexpected exception would kill the thread (no observed catch-all in the loop body; `Inferred` risk, low likelihood).
- **SFX thread death**: `soundLoop` catches `Throwable` per tick (logs "Sound thread crashed!") and keeps looping — the SFX thread is designed to be unkillable by game code. `Verified`.
- **Mod listener failure**: isolated per-listener (non-critical) — one bad mod cannot break a frame. `Verified`.
