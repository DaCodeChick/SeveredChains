# Compatibility Checklist (Consolidated M1–M9 Constraint Set)

Status: Complete (M10, 2026-11-14). This document consolidates the behavior-compatibility constraints of M1–M9 into a single row-level checklist. It is a **constraint inventory, not a design proposal**: no Rust crate, API, or dependency decisions are made. Every row traces to a specific research document + confidence class (the M10 verification criterion). Where M4-05 (`research/psx/05-compatibility-classification.md`) already classifies a behavior, this document carries that row's classification forward (IDs G/T/S/X/R are M4-05's; the `CL-*` IDs introduced here are new). The M4-05 four-class framework (Hardware-accurate / Behaviorally-equivalent / Format-only / Unresolved) applies to the CL-PSX section; the other sections use the research evidence vocabulary (`source-verified`, `format-corroborated`, `Inferred`, `Unresolved`, `Proposed`). No `asset-validated` claims exist in M1–M10 (register R-01).

## 1. Reading the checklist

| Column | Meaning |
|---|---|
| **ID** | Stable row identifier. `G/T/S/X/R` = carried from M4-05 §3 (43 rows); `CL-<domain>-NN` = new in this document. |
| **Constraint** | What a behavior-compatible implementation must preserve (or explicitly, in §7, must *not* be required to preserve). |
| **Source** | The document + section the constraint traces to. The source is authoritative; this document adds no unsourced claims. |
| **Class / Confidence** | M4-05 class for CL-PSX rows (HA = Hardware-accurate, BE = Behaviorally-equivalent, FO = Format-only, UR = Unresolved) plus M4-05 confidence (H/M/L); evidence class for all other rows. |
| **Layer** | 1 = PSX platform, 3 = LoD-specific, 4 = reference-specific (the R1 four-layer model, `psx/01-compatibility-boundaries.md` §1). |
| **Notes** | Risk, disposition by later milestones, register pointer. |

**Evidence note.** Rows are as strong as their source: `@Method`-anchored decompiled contracts (H / source-verified) where the reference copied the original's code; mechanism documentation + `Inferred` hardware attribution (M) for the layer-4 hardware models; `Unresolved` where both candidate behaviors are documented (the UR rows in §2 and the decision items in §6 name the resolving evidence). All layer-1 (PSX hardware) attributions remain `Inferred` pending the external-documentation worklist (Q-20..Q-23, Q-65..Q-67 — §6.3).
