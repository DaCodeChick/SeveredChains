# P0-04 — Implementation Roadmap (Proposed)

Status: **Proposed (P0, 2026-11-14).** Dependency-ordered milestones from the P0 architecture (planning/01), TD set (planning/02), and CD set (planning/03). **No milestone begins until the user approves P0 and then explicitly authorizes the implementation phase.** Each milestone: objective, prerequisites, scope/exclusions, research references, code modules, testable deliverables, unit + integration verification, the compatibility-checklist rows it covers (row-level: planning/06), open dependencies/risks, and the completion gate.

Sequencing rationale (from the research, not convenience): the bit-exact primitives (I0) have no dependencies and de-risk the determinism surface first; the format codecs (I1) de-risk A6 (the unpacked tree is the observable asset contract) before any state reads assets; the SDK framework (I2) is the dependency-free contract layer every later crate needs; the engine core (I3) is the vertical skeleton (frame contract + state machine + Noop backends) — the largest architectural risk, isolated as early as possible; the Fate VM (I4) is the best-evidenced subsystem (M3 xhigh audit) and a leaf the game states call; the PSX models + presentation + audio (I5) is the largest technical-risk cluster; then the game, in the order the research's readiness assessment supports (cross/03 §9): the title/save vertical slice (I6) first (it exercises the whole stack end-to-end), submap/wmap (I7), battle (I8 — the largest single system), the remaining content surfaces (I9), and the mod/patch/asset-validation completion (I10).

Cross-cutting preconditions (cross/03 §10 — the pre-implementation verification steps; none is a design decision): (P1) the reference pin is re-confirmed before the first implementation commit (the Phase-A precedent — a delta census before any pin advance); (P2) the Q-06 per-phase invariant census is scheduled as a parallel research task (it refines the frame-contract tests, I3); (P3) the external PSX documentation worklist is admitted as a separate, user-approved evidence pass before I5 declares done (it does not block I5 *building*); (P4) the asset types (disc images per plan P-02, retail script disassembly, a memcard dump, retail SSSQ + audible duration) are requested from the user in parallel — they gate I10's validation pass, not any earlier milestone.

## I0 — Workspace foundation + bit-exact primitive core

- **Objective.** The Cargo workspace exists and the highest-risk determinism surface (the RNG algorithms, the fixed-point helpers, the Bpp/blend primitives) is implemented bit-exactly against the documented formulas.
- **Prerequisites.** P0 approval; P1 (pin re-confirmation).
- **Scope.** `psxrt` (the `fixedpoint`, `rng`, `bpp`, `blend`, `timing` modules — the R1/R2 helpers; the LCG core + the LCG16 (×9+0x3711) and LCG15 (×0x41c64e6d+0x3039) parameterizations; the `java.util.Random`-family 48-bit LCG with bounded `nextInt(bound)`/`nextFloat(bound)` rejection semantics — the P0-verified identity; the 1/60 s game-time unit + vsyncMode/vsyncCount primitives) and `psxrt-compat` (the policy framework: one module per policy with the evidence/default/knob/divergence-note shape — G6, G4, G11, T2, X6, S7 policies *skeletoned* with their defaults per CD-01..CD-07; the G3/G10/G12/G13/T1/S2/S3/X1/X4/X7 policy entries). The workspace root (members for `psxrt`, `psxrt-compat`; the lint profile; `Cargo.lock`; the file-ending audit integration; the testdata layout convention, TD-20). **Excluded:** every other crate (created when first needed — TD-02), every I/O, every thread.
- **Research references.** M4-05 §2/§3 (R1–R5, G1–G15, T1–T7, S1–S9, X1–X7), psx/01–04 (the formula-level sources), cross/02 §2 (the 43 rows), planning/02 TD-01/02/03/04/20/24, planning/03 (the CD defaults).
- **Code modules.** `crates/Cargo.toml`; `crates/psxrt/{fixedpoint,rng,bpp,blend,timing}`; `crates/psxrt-compat/{policy,same_z,display_clamp,rate_00,gte_precision,predictor,sweep,blend_select,voice_alloc}`; per-crate `tests/` + `testdata/`.
- **Testable deliverables.** Golden vectors (deterministic, derived from the documented formulas at a fixed seed — the manifest records the derivation; *source-derived, never asset-validated*): N=10_000 outputs of each RNG from each documented initial seed (LCG16 seed 3; LCG15 seed 0x24040001; the 48-bit LCG from a fixed 48-bit seed — including the bounded-draw rejection paths); `rsin`/`rcos` golden values over a theta grid (the float×0x1000 short-cast, the "always positive only at constrained call sites" note); the Bpp 4/8/15/24 encode/decode pair over exhaustive 15-bit patterns; the four blend equations over exhaustive (B,F) pairs (the F/4-first truncating order); the 1/60 s unit arithmetic (the `vsyncMode` → rate mapping for the 60/30/20 Hz contexts × speed 1..16).
- **Unit + integration verification.** Property tests (proptest): Bpp round-trip (decode∘encode = identity in-domain); blend monotonicity + the exact-integer semantics; LCG stream invariants (the LCG15 output range ⊂ [0, 0x7fff]; the bounded-draw uniformity bounds). No integration tests yet (no other crates).
- **Rows covered (planning/06).** R1, R2, R3 (algorithm), R4 (algorithm), G1 (mechanism), G2, G10 (equations), the timing-unit half of CL-ENG-02.
- **Open dependencies/risks.** The `java.util.Random`-family LCG's exact `setSeed` masking + `nextLong` derivation must match Java 25's (verified from the JDK spec at implementation start — the algorithm is standard; the risk is low). The 48-bit LCG's `nextFloat(bound)` Java-17+ semantics (the `floorMod`-based path) — pinned in the golden vectors.
- **Completion gate.** `cargo test` green (the full golden + property suites); the policy framework compiles with the CD defaults + divergence notes; zero external dependencies beyond std (TD-04's psxrt side; psxrt-compat depends on psxrt only); the workspace lint + file-ending audit clean; no crate beyond the two exists.
