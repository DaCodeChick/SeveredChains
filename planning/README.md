Status: **Complete, pending user approval (2026-11-15).** Activated 2026-11-14 with approved starting point `4a2acb8` (the M10 commit). This directory contains the complete P0 deliverable set: the proposed Rust architecture, the technical decision records, the compatibility decision dispositions, the implementation roadmap, the verification strategy, and the research-to-implementation traceability matrix. **Nothing here is approved.** The six crate names are fixed user decisions; every internal design, dependency, decision record, and milestone in this directory is a **proposal** awaiting explicit user approval. ## 2. The P0 corrections log (in-place corrections to the research corpus)

P0 discovered and corrected two errors in the M10 corpus, in place, with the correction recorded at the site (not silently):

1. **Battle-RNG identity (2026-11-14).** `seed_800fa754` is a `legend.core.Random` instance — `legend.core.Random` **extends `java.util.Random`** (the 48-bit LCG, multiplier 0x5DEECE66D, addend 0xB). It is **not** a Mersenne Twister. The "Mersenne Twister" label in the M10 documents is the reference's own `@ScriptDescription` text on `scriptSetMtSeed`. The class's `mix32` override of no-arg `nextInt()` (Stafford variant 4) is **dead code** — every consumer uses bounded or float draws. The full RNG surface is **five** instances (not three as the M10 summary stated): `simpleRand` (16-bit LCG, ×9+0x3711, seed 3), `rand()` (15-bit LCG, ×0x41c64e6d+0x3039, initial 0x24040001, the single host-clock `srand` at submap entry), the battle RNG (48-bit LCG, process-clock seed, the `scriptSetMtSeed` = `setSeed(seed ^ 0x75bd924)` re-seed), the turn-order jitter RNG (48-bit LCG, per-battle, seeded from `timestamp_a0` — the layer-4 GH#2481 replacement), and the snow effect RNG (48-bit LCG, per-submap instance). Corrected in place in: `research/cross/01-architecture-review.md`, `research/cross/02-compatibility-checklist.md` (CL-GLP-02), `research/cross/03-implementation-readiness-notes.md`, `research/game/07-inventory-and-items.md` (I38 + related), `research/04-unresolved-questions.md` (Q-70), `research/03-research-plan.md` (the M10 log), `AGENTS.md`.
2. **Compatibility row count (2026-11-14).** The M10 summary's "109 rows (43 + 66 new)" was a transcription error against the document's own row set: the per-milestone coverage table and the M10 verification criterion enumerate **92** new `CL-*` rows (CL-ENG 13, CL-AST 12, CL-SCR 13, CL-AUD 10, CL-SAV 15, CL-MOD 12, CL-GLP 17), giving **135 total**. Corrected in place in: `research/cross/02-compatibility-checklist.md` §12, `research/cross/03-implementation-readiness-notes.md` (2 sites), `research/README.md` (T-XSYS row), `research/03-research-plan.md`, `AGENTS.md`.

Both corrections were committed with the P0-01..04 deliverables at `f67d268` (user commit, 2026-11-15). No register item was opened or closed by the corrections (they fix transcription, not behavior).

## 4. What approval means (the open user decisions)

P0 stops here. The decisions the user is asked to approve or amend:

1. **The architecture** (planning/01) — the 7-crate workspace, the dependency graph with its two refinements, the 21-phase frame driver as the Rust frame contract, the SDK-as-contract-layer property, the error model, the naming conventions.
2. **The 24 technical decisions** (planning/02, TD-01..TD-24) — as a set or per-item. The provisional external-decision notes (TD-24: the `opus` encoder version; the `cpal` device model) are flagged where they occur.
3. **The 10 compatibility dispositions** (planning/03, CD-01..CD-10) — with **CD-02** (the RNG seed source: mirror the reference's host-clock seed + the dev `--seed` override) and **CD-06** (the S7 sweep envelope: the deliberate divergence from the reference's gap) called out as the two rows where the proposal is itself a decision.
4. **The roadmap** (planning/04, I0–I10) — the sequencing and the gates; the cross-cutting preconditions P1–P4 (the P4 asset request is the user's asset-access decision, the P-02/R-01 thread).
5. **The verification strategy** (planning/05) and **the traceability matrix** (planning/06) as the standing acceptance machinery for I0–I10.

Nothing in the implementation phase (I0 onward) begins without explicit approval. The register's 50 open items remain user/asset-gated; the two P0 corpus corrections closed no register items (transcription only).
